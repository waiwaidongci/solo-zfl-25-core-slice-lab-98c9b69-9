# 岩芯样本切片实验室

零依赖 Node.js 服务。`npm start` 后访问 `http://localhost:3025`。

## 两个入口

| 入口 | 说明 |
| --- | --- |
| `/`（旧入口，保留） | 样本建档、切片步骤自由记录、标记交付，接口 `/api/samples*` 行为不变 |
| `/station`（切片台） | 批次级约束作业：批次建档、按工序推进、观察退回复检、交付前核对与锁定 |

## 切片台批次模型

- **批次**：一次建档可含多片切片，共享同批试剂余量与批次台账（操作记录、试剂用量）。
- **工序顺序**：取样 → 切割 → 研磨 → 染色 → 待观察 → 观察（合格终态）。切片状态始终是"下一道待执行工序"，服务端强制按序推进，不能跳步。
- **每次推进绑定三类资源**：
  - 合格人员：人员须具备该工序资质且资质在有效期内；
  - 有效试剂批次：该工序按配方耗试剂（默认 切割 2ml / 研磨 1ml / 染色 3ml，取样、观察不耗；可按染色方法用配方覆盖），同批所有切片共享试剂余量，过期或余量不足即失败；
  - 空闲设备时段：`[startAt, endAt)` 与既有占用重叠即设备冲突。
- **整次失败、整次不变**：任一约束不满足返回 `409 constraint_blocked` 并列出**全部**阻断原因；切片状态、操作记录、试剂余量、设备时段占用均不变。所有写操作在进程内串行事务中执行，先全量校验、后统一提交、临时文件 + rename 原子落盘。
- **观察与退回**：执行观察时给结论。不合格必须指定退回工序（取样/切割/研磨/染色），切片退回该工序重做，`passed=false`；未复检合格不得交付。
- **交付核对与锁定**：交付前核对 ① 所有切片观察合格（退回须已复检）② 试剂用量台账与操作记录一致 ③ 本批设备时段全部结束（设备释放）。任一不满足拒绝交付并说明阻断原因；通过后批次锁定，不能再推进或重复交付。

## 主要接口

- `GET  /api/station/state` 批次 + 人员/试剂/设备/时段/配方
- `POST /api/station/batches` `{project,borehole,coreBox,owner,method,sliceIds:[...]}`
- `POST /api/station/batches/:b/slices/:s/advance`
  `{personId, equipmentId, reagentId, startAt, endAt, pass?, returnTo?, note?}`
- `POST /api/station/batches/:b/deliver`
- `POST /api/station/people|reagents|equipment` 资源登记（试剂支持 `{adjust:true, amount}` 补库）

## 数据与重启

数据持久化在 `data/core-slices.json`（可用 `DB_PATH` 覆盖）。旧数据文件启动时自动补齐批次域字段，不影响旧入口。重启后批次状态、试剂余量、设备占用与交付锁定均保留。


覆盖：正常交付、并发抢设备、同批共享试剂余量不足、试剂过期/无资质/资质过期、失败整次回滚（多重阻断）、观察退回与复检、设备未释放阻断、交付锁定、重启数据不丢、旧入口可用。
